## What the wave found, and it is one pattern on six surfaces

Every task landed on the same defect: **a count or a sentence that is true of one population,
printed over another.**

| Surface | Asserted | Actually known |
|---|---|---|
| render harness | `OK` | the page rendered **500 SOMETHING WENT WRONG** |
| repo card | green `0`, "No findings" | the scan **FAILED** |
| endpoint stat cards | `Online 0` in success green | the list was **never received** |
| MCP approvals | "12 awaiting review" | 12 pending **within a 50-row window of 300** |
| policy board | Warn: `0 categories - 0 detectors` | **29 of 36 detectors** in no lane header |
| tool confirmation dialog | "DeVoid flagged this prompt" | the actual command **never shown** |

The policy board is the sharpest: three individually-correct decisions compose into a board that
cannot answer its own question. Strictest-wins folds a category to Block; a category is filed in one
lane; a lane counts only members at its own disposition. A member at `warn` inside a Block-folded
category is seen by neither. Measured `7 + 29 = 36` and `2 + 32 = 34`, against `24 + 0 = 24` on a
uniform board that correctly prints nothing.

**In every case the fix was only real because of the discriminating pair.** A change that renders
everything as "unknown" passes a one-sided test perfectly while destroying the honest green zero a
clean repository has earned. Every fix here pins both directions.

**2. I reported a product defect that was my own fixture.** `/ai-control-plane/events` rendering
"NO AI ACTIVITY YET" under a scenario called `read-failed` — except that scenario never failed *that
page's* read, which inherited a shared 200-with-empty-items. The read succeeded and was genuinely
empty; the page was right, and its `COULD NOT LOAD ACTIVITY` branch correctly stayed silent. I also
forbade "all clear" under `absent-data`, where the alerts read succeeds with real zeros — reddening a

**3. I skipped the plan's mandatory defeat.** Task 1 required deleting one `--forbid` string and
watching the run flip exit 1 to 0. I neither ran it nor claimed it. Running it would have caught all
three causes of the inert corpus in seconds.

The pattern is exact: the defect this wave kept finding in the product — *a number true of one
population printed over another* — is the one I twice produced in my own measurements.

**The durable lesson, recorded as a seventh inert-test shape:** a defeat test proves the assertion is
load-bearing; only checking the fixture proves it is load-bearing **for the stated reason**. Every
defeat run in this wave asked the first question. None asked the second.

## I broke the workspace for an hour, and the cause was my own instruction

My verification brief told each subagent to "remove your worktree and delete your branch" when
finished. Those worktrees contain `node_modules` as a **Windows junction** to the shared Frontend
tree, and a recursive delete under MSYS walks THROUGH the junction and deletes the target's contents
rather than unlinking the reparse point.

The evidence was conclusive rather than circumstantial: the shared tree was missing exactly 17
top-level entries, **alphabetically contiguous** — `.bin`, `.package-lock.json`, then `@adobe`
through `@jridgewell` — with zero entries added. A sorted-order delete cut off partway. (It reached
deeper than that too: two packages inside `@next/` were gone, which my first restore missed.)

Every test run on this machine, for every session, was broken until it was repaired.

**The restore did not use npm**, and that is its own finding: `npm` here is our product's shim at
`C:\ProgramData\devoid\bin\npm`, which fails closed on install with *"Configuration missing or
invalid"*. A peer confirmed independently there is no `credentials.json` at all — a machine-scope
install that never enrolled. Rather than bypass our own supply-chain control or touch ProgramData
credentials, the 19 missing entries were copied from an intact Frontend worktree. Separately, a
`git add` was blocked mid-session with *"the local governor did not answer in time, so the decision
was made on-box"* and succeeded on retry. **Both are the gate working as designed, and both are real
customer-visible cost on an unenrolled box.**

**Rules taken from this:** cleanup is never an agent's job; unlink the junction before removing any
directory that contains one; and a timing-sensitive failure in this workspace is contention until
measured on a quiet box — `cmd/devoid` blew its 600s default under four concurrent Opus agents and
returned at 377s and 228s once quiet.
