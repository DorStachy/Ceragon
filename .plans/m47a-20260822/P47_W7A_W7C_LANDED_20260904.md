## The two findings that change what the plan says

**1. The containment gate had three doors, not one (7C Task 2).** The wave file describes gating
one detonation site. `sandboxRunner.execute(...)` is called from three: the install-phase
detonation and, outside that block, the npm and PyPI *import-trigger* runs, which were guarded by
an ecosystem check alone. Following the task literally would have skipped the install detonation
and then executed the package anyway through the import-trigger harness — where module-body
supply-chain malware actually fires. **P0-18 would have read closed while open on npm.**

Verified independently: `shouldSkipUncontainedDetonation` is computed once and consulted at all
three call sites, and it fails closed when the runner's capability cannot be determined.

**2. Following Task 1(b) literally would have built the false green the wave exists to kill
(7A).** The spec says a missing manifest's "every array carries" the `coverage-contract-missing`
marker. Taken at its word that puts the marker in `succeeded` — which closes the required-coverage
gap and turns "nobody measured" into PASS. The implementation mirrors the worker's
`missingScannerExecution()` instead: the marker goes in `requested`, `failed` and `required`, never
`succeeded`, and a test asserts that directly with the reason written beside it.

**3. The worker-authoritative invariant is inverted by the spec's wording (7A Task 6).** The task
says read `metadata.runtime` first "with the existing top-level read as a fallback". But
`worker.ts:2712` writes `scannerStatuses`/`scannerExecution` at the top level *last*, commented
"RESERVED and worker-authoritative", so a version-skewed dispatcher cannot overrule the worker's own
measurement. Envelope-first hands that decision back to the dispatcher. Top level wins; the envelope
is the fallback. The Action never writes those keys at the top level, so nothing is lost.

**This is a net gain in honesty and a red suite on this box.** Both halves are true and neither
should be reported without the other.

## Two refusals worth keeping

**A number was not inflated to satisfy a criterion.** Wave 7C exit criterion 6 greps for two or
more call sites of `willRunFullyIsolated`. There is one — but it is now reached for every
ecosystem, which is the substance the criterion was reaching for. Duplicating the call would have
made the number true and the code worse. Reported as a deviation instead.

**The PR trigger did not go on the deploy workflow.** `build-and-deploy.yml` holds `id-token:
write` and shares a `cancel-in-progress` group with live deploys, so a pull-request run there could
cancel a deploy, and six deploy steps would sit one missing `if:` away from firing on a PR. A
separate `pr-checks.yml` with no AWS steps and no OIDC permission carries the guard instead.
