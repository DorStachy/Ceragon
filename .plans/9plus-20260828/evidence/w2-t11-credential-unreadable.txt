    and no tamper.log on this machine was read. The task's EXIT number — exactly

  * NO CONSOLE EVENT ID. Nothing was sent to the Backend. The claim that the
    console renders this event rests on BypassTelemetryEventDto accepting a free
    `type` string, which was verified in the Backend source and NOT end-to-end.
  * NO DEPLOY, NO RELEASE. Neither is needed (no wire contract widens) and
    neither was attempted.
  * `devoid doctor` PRINTS NO ROW for credentialReachability. The block is on
    GET /v1/health/observed, which doctor already fetches and decodes into
    daemon.ObservedRuntimeSnapshot, so the data is there — but no renderer was
    added, exactly as the AbandonedDecisions precedent left it (that block has
    been on the same route for some time and `cmd/devoid` renders it nowhere).
    Note also that on the very endpoint this defect describes, `devoid doctor`
    cannot read this route at all: fetchObservedRuntime calls attachDaemonToken
    and the route is token-gated, so an unreadable token 401s the diagnostic
    too. The off-box event is the load-bearing half; the observed block is for a
    reader who CAN authenticate.
  * `callerBinary` IS NOT RECORDED. The task asks for a third detail key. The
    daemon cannot prove it: a loopback TCP peer carries no process identity on
    Windows (peerUIDMatchesDaemon is a //go:build !linux no-op) and an
    unauthenticated caller's self-declared name is attacker-chosen text on a
    security console. Shipping "unknown" would put a value on a console that
    means nothing, so the key is OMITTED and the reason is written into
    credential_reachability.go. Resolving it needs the kernel-verified client
    identity Task 7 adds on the named pipe.
  * NO CI JOB RUNS EITHER NEW TEST. `wire-lane-tests` filters internal/daemon by
    -run 'OpenAI|Wire|Persistence|TaskInfo' and neither new daemon test matches;
    `cli-entrypoint-tests` runs ./cmd/devoid/... only, and
    cmd/devoid-prompt-guard-host is named by NO job in pr-checks.yml (it is only
    built there). The task asks for a pr-checks.yml leg; the standing agent brief
    forbids appending one while several agents run concurrently — the parent adds
    one consolidated leg. Local runs are the only signal today, and GitHub Actions
    is blocked org-wide on this plan regardless.
